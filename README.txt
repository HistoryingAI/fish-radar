========================================================
  肥魚雷達 FISH RADAR  ·  使用說明（白話版）
========================================================

這個資料夾裡沒有伺服器、沒有資料庫、沒有後台。
它就是「一個網頁」＋「一個採集腳本」＋「一份數據」。


一、現在馬上要看，怎麼做
--------------------------------------------------------
雙擊 index.html 就行。不用裝任何東西，不用開伺服器。

如果打不開或一片空白，先確認同一個資料夾裡有 data\posts.js
（那是數據本體，網頁要讀它）。


二、數據怎麼更新
--------------------------------------------------------
雙擊  更新數據.bat
等一分鐘左右，它會去 B 站和 GitHub 抓一次新的，
然後把 data 資料夾裡的三個檔案覆蓋掉。
跑完之後回到網頁按 F5 重新整理，就是最新的。

想自己調參數的話，開命令提示字元在那個資料夾打：

    python collect.py              抓最近 7 天
    python collect.py --days 1     只抓最近 24 小時
    python collect.py --days 30    抓最近 30 天


三、這些數據是真的嗎（重要，請一定看）
--------------------------------------------------------
真的部分是這兩個平台：

  B 站     → 抓的是官方公開搜索接口。播放 / 彈幕 / 收藏 都是接口
             當下回傳的原值，沒有加權、沒有換算。
  GitHub   → 抓的是官方 Search API。Star / Fork 同樣是原值。
             但公開頁不放它（大陸打不開），只在電腦上開 本機-GitHub.html 看。

沒接的部分是這三個，**公開頁上直接不顯示**（沒有灰色按鈕，也不留空欄位）：

  小紅書   → 需要 X-s / X-t 簽名 + 登錄態，硬爬會被封號
  推特 X   → 官方免費 API 已經不給搜索讀取了
  小黑盒   → App 接口要動態簽名 hkey

也就是說：**這一版沒有用任何假數據去填那幾個平台。**
不顯示就是不顯示，寧可少一欄，也不會假裝有內容。這跟很多演示頁面最大的差別就在這裡。


四、它怎麼判斷「這是二創，不是科技新聞」
--------------------------------------------------------
三步，寫在 collect.py 的 filter_post() 裡：

  1. 標題或簡介裡必須出現角色詞（deepseek娘、大肥鱼、鲸鱼娘…），
     否則跟這個角色無關，直接丟掉。

  2. 出現二創詞（手書、立繪、表情包、同人、MMD、四格…）
     → 判定「強相關」，收。

  3. 出現技術詞（教程、部署、報錯、顯存、微調、API…）又沒有二創詞
     → 判定是科技新聞，丟掉。

  4. 兩邊都不沾 → 標成「相關」但不算強相關，網頁上可以一鍵只留強相關。

想加減關鍵詞，改 config.json 裡的 creative_words / tech_words 就行，
改完重跑一次。


五、它靠四條路把東西找出來（這是這一版最重要的改動）
--------------------------------------------------------
一開始只用「關鍵詞搜索」，結果漏得很慘。實測後改成四條路並用：

  ① 關鍵詞搜索  deepseek娘、大肥鱼、claude娘、gpt龙娘、千问娘…
                最直接，但只認標題和簡介，翻的也只是前 20 條。

  ② 相關推薦    從已經抓到的熱門視頻，順著 B 站的「相關推薦」往外爬
                （每個種子視頻能拽回 40 條）。標題不寫角色名的視頻，
                多半是這樣被撈回來的。

  ③ UP 主名搜索 B 站的視頻搜索居然認 UP 主名字。而「Claude大小姐在運營」
                「ChatGPT龍娘在運營」這類賬號，名字本身就是身份標籤，
                視頻標題卻常常一個角色詞都不帶。按名字再搜一遍，
                能把它們整條時間線撈出來。

  ④ 人工種子    seeds.txt（B 站）與 config.json 裡的 github_seeds（GitHub）。
                前三條都夠不著的，你自己把鏈接貼進去。
                貼進來的會被無條件收錄，而且會當成種子再做 ②③ 的擴散
                ——所以貼一條，往往能順帶拽出一整串。

                GitHub 那邊同理：像 Alterssss/dsh-bili-whale 這種
                「給 DSH 裝一條會自己刷 B 站的魚」的倉庫，簡介裡
                只有「魚」「B 站」，一個角色詞都沒有，關鍵詞永遠搜不到，
                所以放進 github_seeds 手動指定。

實測效果：只用 ① 的時候 67 條，加上 ②③④ 之後 190 條，
而且其中 134 條是 ① 根本搜不到的。

為什麼還是可能漏？
  - 標題、簡介、UP 主名裡完全沒有角色線索的（比如純 AI 生成短片），
    任何算法都認不出來，只能靠 seeds.txt。
  - B 站搜索結果本身會漂：同一條視頻，這次在第 1 頁，下次可能就沒了。
    所以腳本會把「這次掉出去但還在 3 天內」的留著，標記成沿用上次數據。
  - 按 UP 主拉完整投稿列表的接口被 B 站鎖了（連簽名都過不去），
    所以 ③ 只能靠「搜名字」，不能保證把他所有視頻都拿到。


六、去重是怎麼做的
--------------------------------------------------------
每條帖子都有一個身份證號（B 站是 BV 號，GitHub 是 帳號/倉庫名）。
每次跑之前會先讀舊的 data\posts.json：

  沒見過的 → 新建一條，標記 NEW
  見過的   → 不重複收，只更新熱度，順便算出「比上次漲了多少」

所以網頁上卡片右下角那個 ↑123 是「跟上次抓取相比漲了 123」，
不是它今天的總播放量。這是兩個不同的數字，別看混。


七、想放到網路上讓別人也能看（可選）
--------------------------------------------------------
最省事的做法，全程免費：

  1. 註冊 GitHub，點右上角 + → New repository，名字隨便取，
     選 Public（公開倉庫才能免費用 Actions 定時跑）。

  2. 把這個資料夾裡的所有東西傳上去。
     注意 .github 這個資料夾要一起傳（裡面是定時任務的設定）。

  3. 倉庫 Settings → Pages → Source 選 "Deploy from a branch"，
     分支選 main、資料夾選 / (root)，存檔。
     等一兩分鐘，它會給你一個網址，那就是你的網站。

  4. 倉庫上面點 Actions 標籤 → 左邊選「更新肥魚雷達數據」→
     右邊按 Run workflow，先手動跑一次確認沒問題。
     之後它每 6 小時會自己跑，跑完自動把新數據提交回去，
     網頁也就跟著更新了。

成本：域名另算（.com 一年大約 75～99 元人民幣），
主機、定時任務、SSL 全部 0 元。


八、常見問題
--------------------------------------------------------
Q：我明明看到一條很好的，為什麼它沒被收進來？
A：先看它的標題、簡介、UP 主名裡有沒有角色詞。
   三個地方都沒有（比如「人類把一整個 B 站賬號交給 AI」），
   算法就是認不出來，這是原理上的限制，不是 bug。
   解決辦法：把那條鏈接貼進 seeds.txt，重跑一次。

Q：封面圖顯示不出來，只有一塊深藍色？
A：B 站的圖牀有時會拒絕外鏈。顯示不出來時卡片會自動退回純色底，
   不影響閱讀和點擊，點進原帖就看得到圖。

Q：為什麼 DeepSeek 娘的帖子特別多？
A：因為她的二創基数本來就大（大肥魚、鯨魚娘這些叫法都在她名下）。
   其他角色量少是實情，不是漏抓。

Q：這跟「蓝色大肥鱼.com」有什麼關係？
A：沒有關係。那個是人工審核的同人圖庫，我們是自動聚合的熱帖索引。
   本專案不搬運它的任何圖片或內容。

Q：抓太頻繁會不會被封？
A：B 站每次請求間隔 2.2 秒（config.json 裡的 bilibili_delay）、
   GitHub 間隔 3.2 秒，並且只用公開接口。
   一天跑幾次沒問題，但別在五分鐘內連著跑七八次。

   如果真的被攔了，B 站會回一個 412，腳本不會硬撞——
   它會立刻停手並在網頁最上面顯示一條橘色提示：
   「這次 B 站沒抓完整，畫面顯示的是上一次的內容」。
   看到這條就等幾分鐘再按一次更新，資料不會因此丟掉。

Q：為什麼有時候詳情裡寫「這次搜索沒再出現」？
A：B 站的搜索排名是浮動的，同一條帖子這次可能排到第 3 頁去。
   只要它還在 3 天內，腳本就會把它留著，標記成沿用上次的數據，
   免得你重新整理一次，東西就莫名消失了。

Q：雙擊 bat 說找不到 Python？
A：去 python.org 下載安裝，安裝第一頁記得勾
   「Add python.exe to PATH」，裝完重新雙擊。

.github\workflows\update.yml   每 6 小時自動跑的設定


十、前端這一版新增了什麼（2026-10-24）
--------------------------------------------------------
① 首屏拆分
   以前 311 條一次塞 256 KB，瀏覽器要等下載完才畫第一屏。
   現在首屏只同步載 25 KB（最熱的 30 條），畫完之後才在背景補其餘 226 KB。
   條數一多差別就很明顯。

② 導出 CSV
   右下角「⬇ 導出 CSV」，導出的是**當前篩選結果**（角色＋平台＋時間＋相關度），
   不是全部。Excel 直接開，不會亂碼。

③ 分享卡片
   連結貼到微信／B 站／Discord 時會展開 og-cover.jpg。
   ⚠️ 上線後要把 index.html 裡的 og:image 改成絕對網址，否則抓不到。
   改了數據想重畫：python make_og.py

④ 頁尾免責聲明
   講清楚「不儲存本體、只存連結、收錄不代表背書、可要求移除」。

⑤ 兩個測試
   python test_page.py      結構體檢，不聯網
   node test_render.js      渲染＋補載流程，不開瀏覽器
   改完 index.html 建議兩個都跑一次。


十一、第二批前端改動（2026-10-24 下午）
--------------------------------------------------------
① 简体 / 繁体 切换（右上角「繁 / 简」按鈕，會記住選擇）
   B 站抓下來的是简体，界面原本是繁体，两边混着看很别扭。
   现在：
     - 界面文字：一张预先生成的「繁→简」字符表（data/i18n.js，1.5 KB，
       只覆盖本站用到的 119 个字），切到简体时逐字替换。
     - 帖子标题：构建时用 OpenCC 预先转好繁体，存在每条的 title_t 字段里，
       切到繁体时直接读，不是浏览器里瞎转。
   为什么要分两套：OpenCC 是词典级转换（「头发」→「頭髮」不会错），
   浏览器里只能逐字替换，会转错。所以贵的那步放在构建时做一次。

② 深色 / 浅色 切换（右上角 ☀️ / 🌙，會記住選擇）
   浅色不是把背景调白就完事，通知条、统计卡、弹窗、表格线都单独调过。

③ 一次只显示 20 条 +「▶ 載入更多」
   以前 284 条一口气全塞进 DOM，滚动发沉、也翻不到底。
   现在每页 20 条（宽屏 4 列 × 5 行），底部显示「已顯示 20 / 284 條」，
   点一次加 20。换角色、换平台、换时间，都会退回第 1 页。

顺带改的：
   - 分平台榜里的标题也跟着简繁切换走（之前漏了）
   - 导出 CSV 的标题栏也跟当前语言走
   - 切语言时 <html lang> 和标签页标题一起换

注意：改了帖子数据要重新跑一次
   python localize.py    生成繁体标题 + 界面字表
   python split_posts.py 重新拆分首屏
   （collect.py 现在只自动调 split，不自动调 localize——
     因为 localize 依赖 vendor/opencc，多一层依赖，手动跑更清楚）


十二、推廣位（首頁最上面那張活動卡）
--------------------------------------------------------
位置：頁頭下面、橘色提示上面。目前放的是 B 站「大肥魚挑戰 · 徵稿啟動」。

加 / 換 / 撤，只改 promos.js 一個檔案，不用動 index.html：

   window.FISH_PROMOS = [
     {
       tag:   "推廣 · 外部連結",
       title: "活動名稱",
       desc:  "一句話說明",
       btn:   "前往 B 站官方活動頁",
       url:   "https://...",
       img:   "assets/圖片.jpg",
       source:"主辦方"
     }
   ];

   整個撤掉：改成 window.FISH_PROMOS = []; 那一區塊就自動消失。

三條規矩（照著做就不會出事）：
 ① 只做超連結。頁面統一加 target="_blank" rel="noopener noreferrer nofollow"，
    新開分頁跳出去。**沒有 iframe**，不會把 B 站框在我們頁面裡。
 ② 圖片放 assets/ 本地。直接外鏈別人圖床容易 403，也不禮貌。
 ③ 卡片上一定保留「外部連結」標籤和「點擊會離開本站」的說明——
    讓人知道自己在點什麼，這是導流和騷擾的分界線。

版權：圖片是主辦方的，這裡只做指路，不複製內容、不做付費牆。
      對方要求下架，把 promos.js 對應那項刪掉，一分鐘的事。


十三、搜索 / 排序 / 過期提醒（2026-10-24 晚）
--------------------------------------------------------
① 搜索框（三百條以後這是必需品）
   - 搜標題、作者、來源路徑；簡繁兩版標題都搜得到
   - 空格隔開 = 同時滿足：「大肥魚 手書」= 兩個詞都要有
   - 按 / 直接跳到搜索框
   - 搜不到時給的是「清空全部篩選」按鈕，不是一句空話

② 三種排序（熱度 / 最新 / 漲幅）
   - 熱度：平台自己的口徑（播放 / star）
   - 最新：按發佈時間
   - 漲幅：跟上一次抓取相比漲了多少，新出現的排最前
   三種都只排「同一批結果內部」，不承諾跨平台公平。

③ 數據過舊提醒
   抓取超過 24 小時 → 頁面頂部出現黃條，頁頭時間變黃
   超過 72 小時 → 轉成紅橘色，語氣加重
   熱度站最怕用戶看不出新舊，轉發時沒人會替你解釋。

④ 卡片「來源」小標
   每張卡上標一條：🔎 搜尋 / 🕸 相關推薦 / 👤 UP 主 / 📌 手動釘選 / 🐙 GitHub
   鼠標懸停能看到完整來源（比如「相關：BV1xxx」）。
   作用是讓人一眼看出這條是靠關鍵詞撞上的，還是靠關係網撈回來的。

⑤ 上線前必做：og:image 改絕對網址
   python set_og.py --check           看現在是什麼
   python set_og.py https://你的域名   改成絕對網址，順便補 canonical
   不改的話，鏈接貼到微信／B 站／Discord 抓不到圖，分享出去是白板。
